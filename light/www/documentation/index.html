HA Light

Driver version 1 · Setup and programming guide

A native Control4 light for Home Assistant lights and dimmers, with paddle events and connections to an existing Control4 light.

Select a device

  1. Install HA Coordinator and connect this driver's Device Link to it. Coordinator 114 or newer provides discovery. Older coordinators retain manual entity control.
  2. Open Actions → Select Device. Click … beside Device to open Composer's searchable selector, select a device, then confirm both dialogs. The outer dialog is part of Composer's action UI.
  3. Check Selected Device, Status and the capability summaries in Properties. Use Refresh Entities to update discovery. For an exact Entity ID or the fallback dropdown, use Actions → Show Advanced Properties.
  4. Choose the operation mode for the intended behavior. Mode Description explains the current selection.

Ordinary HA device control and discovery work without HA Gesture Bridge. Physical button events require a source that exposes those events and a configured control in the optional integration.

The searchable device list loads when you open Select Device or run Refresh Entities. Startup and reconnection refresh only your selected entity. Discovery requests only relevant entity types and attributes; a failed filtered request is reported rather than replaced with a full HA download. If discovery fails, use the Coordinator's Print Diagnostics action to check its HTTP result.

This selector offers native HA lights, main on/off switches, and physical gesture controls. An on/off switch appears as a native light in Navigator with brightness controls disabled; no relay-to-light driver is needed. It omits settings, diagnostics, hidden/disabled entities, standalone helpers and lights or groups exported from C4. Native HA lighting groups remain eligible. Use gesture Controller Links to control an existing C4 light directly. Existing saved selections and programming are preserved.

Properties and diagnostics

The default screen shows setup, operation mode, the selected device, status, capability summaries and the Debug Mode logging toggle. Selected Device uses a known friendly name, or the exact entity ID when a name is unavailable. A current gesture snapshot or accepted gesture shows Ready; direct HA load feedback shows On or Off.

Actions → Show Advanced Properties reveals manual Entity ID, fallback Entity Selection, catalog settings, discovery status, gesture counters and driver version. Hide Advanced Properties returns to the compact screen. Values and programming are preserved; reloading the driver starts with advanced properties hidden.

For support, open the Lua tab and use Actions → Print Diagnostics. It prints the current setup, hidden settings, detailed status and connection/readiness information even when Debug Mode is Off. This action sends no light commands, refreshes or full HA event payloads.

A single tap sends a logical push/click. Holding sends push; reported release sends release. The target light driver handles dimming and stopping. Prepare the physical switch

If the paddles should control smart bulbs or another C4 light, configure the wall switch's manufacturer-supported smart-bulb or detached-relay mode so its paddles do not cut power to the load. Enable scene reporting as required by that device. This driver does not change relay settings. Check the model and firmware's instructions; parameter numbers and available gestures vary.

For connected-C4 control, the target light can remain entirely in C4. Exporting it to HA or configuring a DeviceSide dimming target is unnecessary for that route. Disable any existing automation that would also react to the same paddles and control the light; save its configuration first so it can be restored.

Programming and capabilities

Properties show Selected Capabilities for load controls, Button Capabilities for reported gestures by button, and LED Status for configured indicator channels and their color, on/off and brightness support. Direct HA control needs no companion. Button gestures and indicator mappings require HA Gesture Bridge. Waiting, unavailable and unconfigured features are labeled separately. In connected-C4 mode the target light owns its load capabilities.

Light provides the native lighting Commands, Conditionals, Loops and standard paddle events. Brightness and timed ramps depend on the selected HA light's advertised capabilities and service support. Unknown/unavailable feedback does not invent a confirmed level.

Indicator LED color commands use explicitly configured HA Gesture Bridge channels. Backlight commands and continuous dimming of an HA load have no execution backend in this version. In connected-C4 mode, the target light owns its dim/stop implementation. Native conditions use the selected app target's reported state and brightness when available. Color and white-temperature controls follow the connected light's current capabilities and confirmed feedback. Temperature and transition limits come from that target. After updating this driver, refresh Navigators to display newly supported color controls. Color commands remain local to C4 and do not change its nighttime On mode.

Available gestures come from the source's declared capabilities. Only reported holds/releases are forwarded. Extra tap counts and custom buttons remain separate programming events. This version does not invent missing physical edges. Initial state, restored history and metadata snapshots do not fire old gestures.

One physical control appears as one configured aggregate. Multiple source entities, such as upper and lower paddles, can feed it. A linked HA load is optional. The picker only combines entities when metadata proves equivalence; similar names alone are not enough.

Use Actions → Print Diagnostics for a one-time report. For ongoing logs, set the visible Debug Mode = On and open the Lua tab. receive shows the HA event, decision shows validation, and forward shows the outgoing Controller Link command. MATCH_LED_STATE can drive configured indicators when LED Feedback Source is enabled; otherwise it is ignored. Turn Debug Mode Off after testing.

Optional latency test

With HA Gesture Bridge 0.1.1 or newer, use Show Advanced Properties, then set Debug Mode = On and Latency Diagnostics = On. Fresh accepted gestures are acknowledged to HA through the existing Coordinator. Snapshots, duplicate/rejected events and older bridge versions do not generate ack traffic. Turn both settings Off when finished.

C4 logs UTC receive/processing/forwarding timestamps and local processing duration. Integration diagnostics in HA expose latency.latest_latency_samples: publication-to-ack round-trip time measured on HA's own clock, plus HA publish/ack and C4 timestamps. The round trip needs no clock synchronization and bounds forward delivery; it is not an exact one-way time. Clock-dependent ha_to_driver_ms estimates can include clock skew.

These measurements exclude the physical press before the switch reports its scene, and the physical light response after forwarding. queued=true means C4 queued an ack; confirm receipt in HA diagnostics.

Single-tap response time

Scene-capable switches may wait to classify multiple taps before reporting a single tap. Check where the delay occurs before changing relay or scene settings. A source's single-tap-only option may also disable hold/release and multi-tap programming.

The connected C4 light owns its click fade rates. Shorter fades change transition duration; they do not remove an upstream pause before the command arrives.

HA Gesture Bridge and DeviceSide

Install HA Gesture Bridge through HA Marketplace as a custom integration repository, then configure controls in Settings → Devices & Services. It normalizes events; it does not run a dimming loop. DeviceSide/DeviceSide is the upstream project whose structure this companion derives from, and remains a separate optional integration for supported HA dimming execution. Do not configure two execution paths to control the same target from the same gesture.

Selected-state recovery

After HA reconnects, the driver needs a fresh selected-entity snapshot before forwarding gestures. A missing response retries only that entity, every five seconds for at most five attempts. A fresh snapshot cancels retries and never replays the saved gesture. The Status shows snapshot recovery separately from transport disconnection. Coordinator Print Diagnostics includes selected-state HTTP results; entity-discovery counters do not measure these reads. Normal operation does not poll the entity or rebuild the device list.

Updates and support

Switch 107 upgrades the original Switch 106 in place. Light 1 is a new installation. Coordinator 114 preserves existing family APIs. Development packages may be reloaded at the same version; use the delivered checksums to identify a build.

Indicator LEDs

HA Gesture Bridge discovers supported indicators automatically. Check LED Status for available controls. Independent color and behavior commands require the updated companion and C4 package.

Properties → LED Behavior is visible on the main screen. Use Device Setting is the default and leaves the hardware mode unchanged. Supported choices include Follow Load, Follow Load (Inverted), Always On and Always Off. Selecting a behavior explicitly applies it; startup, reconnect and snapshots do not reapply it.

Set LED Current Color changes the device color without changing its behavior. Brightness changes are independent too. On a ZEN76 these write parameters 14 and 15; behavior is parameter 2. To turn an indicator off, select Always Off or use Set LED Behavior in Programming. Fixed-color LEDs use behavior commands rather than color commands.

Use LED On Color and LED Off Color in Properties to open the color picker, then click Set. These save tracking colors without changing LED behavior or immediately writing hardware. Black means off when tracking. Colors adjust to the supported palette. Devices with multiple indicators also show LED Indicator to configure each separately. The controls appear when current LED capabilities are available.

Set LED On Color and Set LED Off Color save C4 tracking preferences without a hardware write. Black is allowed in those preferences to mean off. Other indicator choices use friendly labels and stable IDs; saved selections survive label changes. Hardware confirmation comes only from HA feedback.

In Control Connected C4 Light mode, choose LED Behavior = Follow Bound Device. LED Feedback Source then appears on the main screen; choose the Top, Bottom or Toggle Controller Link connected to the target light. A disabled source defaults to Top on first selection. Actual target feedback applies each indicator's saved On/Off colors using explicit indicator behavior commands. Use Refresh LED Feedback after changing bindings. Selecting Use Device Setting stops C4 tracking without restoring an old hardware mode.

Per-channel Set LED Behavior applies a device setting once. Follow Bound Device, when enabled, can override it on later target feedback. LED controls never command a relay or target lamp. See the HA Gesture Bridge setup guide.

Multi-button controls

Additional buttons expose independent named programming events, including all five ZEN32 buttons. Native light events and direct Controller Links use Top, Bottom and Toggle.
