HA Switch

Driver version 107 · Setup and programming guide

On/off control for Home Assistant switches, with device discovery and optional paddle events. Existing Switch programming and connections are retained.

Device selection prefers a gesture-enabled representation of the physical switch when HA's catalog reports its preferred representation. Otherwise the ordinary switch remains available. Selecting the device chooses its supported operation mode; you can change that mode afterward. Existing configured Entity IDs are preserved during discovery.

Select a device

  1. Install HA Coordinator and connect this driver's Device Link to it. Coordinator 114 or newer provides discovery. Older coordinators retain manual entity control.
  2. Open Actions → Select Device. Click … beside Device to open Composer's searchable selector, select a device, then confirm both dialogs. The outer dialog is part of Composer's action UI.
  3. Check Selected Device, Status and the capability summaries in Properties. Use Refresh Entities to update discovery. For an exact Entity ID or the fallback dropdown, use Actions → Show Advanced Properties.
  4. Choose the operation mode for the intended behavior. Mode Description explains the current selection.

Ordinary HA device control and discovery work without HA Gesture Bridge. Physical button events require a source that exposes those events and a configured control in the optional integration.

The searchable device list loads when you open Select Device or run Refresh Entities. Startup and reconnection refresh only your selected entity. Discovery requests only relevant entity types and attributes; a failed filtered request is reported rather than replaced with a full HA download. If discovery fails, use the Coordinator's Print Diagnostics action to check its HTTP result.

This selector offers main on/off device controls and non-dimmable HA lights, plus physical gesture controls. It omits settings, diagnostics, hidden/disabled entities, standalone helpers and lights or groups exported from C4. Native HA lighting groups remain eligible. Use gesture Controller Links to control an existing C4 light directly. Existing saved selections and programming are preserved.

Properties and diagnostics

The default screen shows setup, operation mode, the selected device, status, capability summaries and the Debug Mode logging toggle. Selected Device uses a known friendly name, or the exact entity ID when a name is unavailable. A current gesture snapshot or accepted gesture shows Ready; direct HA load feedback shows On or Off.

Actions → Show Advanced Properties reveals manual Entity ID, fallback Entity Selection, catalog settings, discovery status, gesture counters and driver version. Hide Advanced Properties returns to the compact screen. Values and programming are preserved; reloading the driver starts with advanced properties hidden.

For support, open the Lua tab and use Actions → Print Diagnostics. It prints the current setup, hidden settings, detailed status and connection/readiness information even when Debug Mode is Off. This action sends no light commands, refreshes or full HA event payloads.

To operate an existing C4 light from HA gestures, add HA Light and use its Control Connected C4 Light mode and Controller Links. Switch retains its original incoming keypad connections for its HA load.

Control another C4 light

Use the separate HA Light driver for its dedicated Top/Bottom/Toggle Controller Link inputs. Its native light proxy also provides native lighting programming.

Switch retains its original Relay 1 and incoming Button Link connections for controlling its HA load. Do not replace a working Switch instance with Light in place. Add Light as a new device and configure it separately.

Prepare the physical switch

If the paddles should control smart bulbs or another C4 light, configure the wall switch's manufacturer-supported smart-bulb or detached-relay mode so its paddles do not cut power to the load. Enable scene reporting as required by that device. This driver does not change relay settings. Check the model and firmware's instructions; parameter numbers and available gestures vary.

For connected-C4 control, the target light can remain entirely in C4. Exporting it to HA or configuring a DeviceSide dimming target is unnecessary for that route. Disable any existing automation that would also react to the same paddles and control the light; save its configuration first so it can be restored.

Programming and capabilities

Properties show Selected Capabilities for load controls, Button Capabilities for reported gestures by button, and LED Status for configured indicator channels and their color, on/off and brightness support. Direct HA control needs no companion. Button gestures and indicator mappings require HA Gesture Bridge. Waiting, unavailable and unconfigured features are labeled separately. In HA Light's connected-C4 mode the target light owns its load capabilities.

Switch retains Turn On, Turn Off and Toggle commands, Relay/Button Link connections, and confirmed Is On/Is Off conditions and While loops. Unknown or unavailable state evaluates false. Include a delay in a waiting loop.

Use HA Light for brightness, timed ramps and the native light programming layout. The two drivers have different proxy identities; saved Switch programming is not migrated automatically.

Available gestures come from the source's declared capabilities. Reported holds/releases are available for Composer programming; Switch does not forward them to another light. Extra tap counts and custom buttons remain separate programming events. This version does not invent missing physical edges. Initial state, restored history and metadata snapshots do not fire old gestures.

One physical control appears as one configured aggregate. Multiple source entities, such as upper and lower paddles, can feed it. A linked HA load is optional. The picker only combines entities when metadata proves equivalence; similar names alone are not enough.

SymptomCheck
Clicks reach C4 but the light does not respondProgramming Events Only intentionally sends no light commands. For another C4 light, add HA Light, select its Control Connected C4 Light mode and connect its Controller Links.
Only top double/triple events appearCheck the HA control's mappings. An old proof configuration only declared those two events. Configure both native paddle sources and refresh the driver.
A snapshot is ignoredExpected: snapshots establish current capabilities/state and must never replay an old press.
Hold starts but release does not stop the lightCheck the source declares and reports release, then check the target driver's Button Link implementation. Source loss cancels tracked output holds; it cannot recreate an unreported physical release.
Double-tap is accepted but no automatic click is sentExpected: double/triple taps fire programming events only. This avoids an extra load action when a scene is programmed on a multi-tap.
Picker is empty or reports a coordinator errorCheck the Device Link, HA connection and Coordinator version. Refresh Entities, or enter the Entity ID manually. Companion discovery metadata is optional.

Use Print Diagnostics in Actions to inspect hidden discovery status and gesture counters. For ongoing logs, enable the visible Debug Mode and open the Lua tab. Turn Debug Mode Off after testing.

Single-tap response time

Scene-capable switches may wait to classify multiple taps before reporting a single tap. Check where the delay occurs before changing relay or scene settings. A source's single-tap-only option may also disable hold/release and multi-tap programming.

The connected C4 light owns its click fade rates. Shorter fades change transition duration; they do not remove an upstream pause before the command arrives.

HA Gesture Bridge and DeviceSide

Install HA Gesture Bridge through HA Marketplace as a custom integration repository, then configure controls in Settings → Devices & Services. It normalizes events; it does not run a dimming loop. DeviceSide/DeviceSide is the upstream project whose structure this companion derives from, and remains a separate optional integration for supported HA dimming execution. Do not configure two execution paths to control the same target from the same gesture.

Updates and support

Switch 107 upgrades the original Switch 106 in place. Light 1 is a new installation. Coordinator 114 preserves existing family APIs. Development packages may be reloaded at the same version; use the delivered checksums to identify a build.

Indicator LEDs

HA Gesture Bridge discovers supported indicators automatically. Check LED Status for available controls. Independent color and behavior commands require the updated companion and C4 package.

Properties → LED Behavior is visible on the main screen. Use Device Setting is the default and leaves the hardware mode unchanged. Supported choices include Follow Load, Follow Load (Inverted), Always On and Always Off. Selecting a behavior explicitly applies it; startup, reconnect and snapshots do not reapply it.

Set LED Current Color changes the device color without changing its behavior. Brightness changes are independent too. On a ZEN76 these write parameters 14 and 15; behavior is parameter 2. To turn an indicator off, select Always Off or use Set LED Behavior in Programming. Fixed-color LEDs use behavior commands rather than color commands.

Switch provides immediate color, brightness and hardware behavior commands for supported indicators. For On/Off tracking colors and Follow Bound Device, use HA Light and its Controller Links. Switch does not expose tracking-color settings.

Hardware confirmation comes from HA feedback. LED commands never control a relay or target lamp. See the HA Gesture Bridge setup guide.

Multi-button controls

Additional buttons expose independent named programming events, including all five ZEN32 buttons. Native light events and direct Controller Links use Top, Bottom and Toggle.
